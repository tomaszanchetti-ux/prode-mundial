# Prode Mundial - Tu Mundial, Mundial Real + Marathon Mode UX Spec

## Documento 8

Especificación UX/UI de evolución para las superficies de torneo del producto.

Este documento organiza tres piezas:

- `Tu Mundial`
- `Mundial Real`
- `Marathon Mode`

Su objetivo es diferenciar con claridad qué conviene implementar ahora y qué debe esperar a infraestructura adicional.

---

# 1. Propósito del documento

Este documento traduce a una guía ejecutable tres nuevas superficies UX del producto.

Define:

- propósito de cada superficie
- relación entre ellas
- dependencias técnicas reales
- orden recomendado de implementación

No redefine:

- scoring
- deadlines
- reglas competitivas
- ligas como núcleo social

---

# 2. Principio UX central

La app debe responder dos preguntas distintas sin mezclarlas:

## A. Tu Mundial

`¿Cómo queda el torneo según mis predicciones?`

## B. Mundial Real

`¿Cómo va realmente el torneo?`

La experiencia debe permitir navegar entre ambas, pero su implementación NO tiene el mismo costo ni la misma urgencia.

---

# 3. Decisión de roadmap

## 3.1 Implementar ahora

Conviene implementar antes de `Epic 4`:

- `Marathon Mode`
- `Tu Mundial`
- soporte de `home` pre-torneo y navegación asociada

Razón:

- estas piezas atacan el loop central de uso previo al torneo
- no dependen de la capa social para generar valor
- cambian la jerarquía visible del producto

## 3.2 Diferir

Conviene NO implementar todavía:

- `Mundial Real`

Razón:

- depende de ingestión oficial de resultados
- depende de sync backend confiable
- depende de read models oficiales persistidos
- está mucho más cerca de `Epic 8` que del frente actual

---

# 4. Tu Mundial

## 4.1 Objetivo

Mostrar tablas proyectadas de fase de grupos en base a predicciones del usuario.

Debe sentirse:

- personal
- clara
- viva
- muy escaneable en mobile

## 4.2 Superficie recomendada

Sección propia de torneo con navegación clara.

Opciones válidas:

- tab dedicada
- segmented control dentro de una sección de torneo

Naming binding:

- `Tu Mundial`

No usar:

- `Simulación`
- `Mis resultados`
- `Tabla`

## 4.3 Componente base

La unidad principal debe ser `GroupStandingsCard`.

Debe soportar al menos:

- variant `predicted`
- header de grupo
- progreso del grupo
- tabla resumida mobile-first
- resaltado claro de top 2

## 4.4 Reglas mobile-first

No construir una tabla desktop comprimida.

Versión recomendada:

- filas muy escaneables
- columnas fijas visibles:
  - equipo
  - PJ
  - DG
  - Pts
- detalle expandible o scroll horizontal controlado para el resto

## 4.5 Estados obligatorios

- empty
- partial
- complete

Copy orientativo:

- `Completa más partidos para ver cómo se acomoda el grupo`
- `Todavía faltan resultados para definir posiciones`
- `Ya puedes ver quiénes clasificarían según tus pronósticos`

---

# 5. Marathon Mode

## 5.1 Objetivo

Convertir la carga secuencial de predicciones en una experiencia rápida y con sensación de avance.

## 5.2 Componente recomendado

`MarathonPredictionModal`

Debe incluir:

- progreso global
- contexto del grupo
- matchup
- kickoff
- input de score
- CTA guardar
- salida clara del flujo

## 5.3 Relación con Tu Mundial

Después de cada guardado:

- la proyección del grupo debe actualizarse
- preferentemente por lectura backend estable
- si hay actualización optimista visual, nunca debe sustituir la verdad de backend

## 5.4 Resultado esperado

El usuario debe sentir:

- que avanza rápido
- que está construyendo algo
- que completar grupos tiene recompensa visual inmediata

---

# 6. Mundial Real

## 6.1 Objetivo

Mostrar el estado real del torneo:

- tablas reales
- resultados oficiales
- clasificados reales
- próximos partidos

## 6.2 Estado documental

Este feature queda aprobado como dirección de producto, pero NO como prioridad inmediata de implementación.

## 6.3 Dependencias mínimas antes de arrancar

Debe existir primero:

- estrategia de proveedor oficial o fuente confiable
- normalización backend
- sync periódico
- persistencia estable de standings reales
- estado de actualización visible

## 6.4 Ubicación recomendada en roadmap

`Mundial Real` debe entrar:

- junto con ingestión real
- o inmediatamente después

Por lo tanto, su ubicación natural es:

- `Epic 8`
- o una épica posterior derivada de `Epic 8`

## 6.5 Qué sí conviene dejar listo desde ahora

Solo la preparación estructural:

- naming oficial
- patrón visual diferenciado
- idea de `TournamentModeTabs`
- compatibilidad de componentes reutilizables

Pero sin construir todavía la capa de datos real.

---

# 7. Arquitectura de navegación recomendada

## 7.1 Zona torneo

Debe existir una navegación clara entre:

- `Tu Mundial`
- `Mundial Real`

Componente recomendado:

- `TournamentModeTabs`

## 7.2 Regla temporal

Antes de que exista `Mundial Real`, la navegación puede convivir de alguna de estas formas:

- mostrar solo `Tu Mundial`
- mostrar `Mundial Real` como placeholder no navegable todavía
- ocultar la segunda variante hasta que exista backend real

Recomendación para MVP actual:

- mostrar solo `Tu Mundial`
- no introducir placeholder si no aporta valor

---

# 8. Impacto sobre componentes y contratos

## 8.1 Componentes a construir ahora

- `TournamentModeTabs` solo si de verdad se usa desde ya
- `GroupStandingsCard`
- `StandingsRow`
- `MarathonProgressHeader`
- `MarathonPredictionModal`

## 8.2 Contratos backend a construir ahora

- progreso global pre-torneo
- listado secuencial de pendientes para marathon
- standings proyectados por grupo para `Tu Mundial`

## 8.3 Contratos backend a postergar

- standings reales oficiales
- timestamps de actualización externa
- status `live` / `updated` / `official`

---

# 9. Orden recomendado de implementación

## Fase A

`Home pre-torneo + progreso + entry points`

## Fase B

`Marathon Mode`

## Fase C

`Tu Mundial` con standings proyectados server-driven

## Fase D

Retomar `Epic 4`

## Fase E

`Mundial Real` cuando exista ingestión real

# 11. Instrucción operativa para Codex

No implementar estas tres piezas como un bloque único.

Separarlas por costo y dependencia:

1. `Marathon Mode`
2. `Tu Mundial`
3. `Mundial Real`

Esto evita:

- mezclar UX de alto valor inmediato con infraestructura no disponible
- introducir deuda de producto por apuro
- bloquear el roadmap social por una pieza editorial todavía dependiente de ingestión oficial
