## Decisión de secuencia

Antes de iniciar la implementación funcional de `Epic 4 — Leagues, Invite Flow, Membership & League Detail`, se ejecuta una pasada UX/UI fuerte orientada a:

- elevar la percepción de producto
- consolidar un sistema visual más consistente
- pulir los momentos críticos del loop principal
- resolver banderas / identidad de selecciones de forma robusta
- limpiar navegación, copy, loading y empty states
- ordenar la capa social visible sin mezclar todavía features reales de ligas

Regla de secuencia:

1. cerrar `UX/UI Elevation V3`
2. revalidar el estado visual y operacional resultante
3. recién entonces abrir `Epic 4`

---

## Límites de alcance

### Incluido en V3

- visual system uplift
- spacing / surfaces / typography recalibration
- flags / country identity system
- hero de home más editorial
- modal de predicción y score picker más premium
- compactación de fixtures
- standings / leagues polish
- navegación, copy, loading y empty states

### No incluido en V3

- create league real
- join por código real
- join por link real
- detalle de liga real
- ownership rules reales
- reglas nuevas de producto

### Excepción aceptada

El único soporte de backend/datos explícitamente aceptado en esta fase es el necesario para:

- `team -> flag asset`
- `fifaCode / iso2 / iso3`
- consistencia de naming de selecciones

## Orden ejecutivo

### Fase 1 - Foundation

`STO-UX-011`

- recalibrar tokens, superficies, spacing y tipografía
- consolidar primitives compartidas
- bajar ruido de contenedores y strokes

`STO-UX-012`

- implementar sistema robusto de banderas
- resolver identidad de equipos con soporte de datos
- crear helper central y fallbacks elegantes

`STO-UX-013`

- adelgazar header
- aligerar bottom nav
- alinear jerarquía global de CTA

### Fase 2 - Critical Product Moments

`STO-UX-014`

- rediseñar `Home` V3
- hacer que el próximo partido domine el primer viewport
- bajar texto explicativo
- dejar el progreso como soporte

`STO-UX-015`

- elevar quick prediction y Marathon
- refactorizar score picker
- reforzar guardado, continuidad y microinteracciones

### Fase 3 - Scanability

`STO-UX-016`

- compactar lista de partidos
- redefinir estados
- bajar peso de no-acciones
- integrar mejor predicción ya cargada

### Fase 4 - Social Layer

`STO-UX-017`

- pulir standings
- reordenar ligas
- reforzar el tono de competencia social
- mantener explícita la frontera con `Epic 4`

### Fase 5 - Cierre

`STO-UX-018`

- empty/loading states reales
- copy cleanup
- auditoría visual global
- QA mobile-first final

---

## Dependencias críticas

- ninguna pantalla de V3 debe avanzar sin `STO-UX-011`
- `Home`, `Prediction`, `Fixtures` y `Social layer` dependen del sistema de banderas de `STO-UX-012`
- la limpieza global de navegación y CTA (`STO-UX-013`) debe existir antes de cerrar pantallas
- `STO-UX-018` cierra la pasada solo cuando todo lo nuclear ya está resuelto

---

## Resultado esperado al cierre

La app debe sentirse:

- menos MVP oscuro
- menos dashboard
- más deportiva
- más mobile-first
- más clara
- más premium
- más lista para abrir `Epic 4` sin arrastrar deuda visual fuerte
