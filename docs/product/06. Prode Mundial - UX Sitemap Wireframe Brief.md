# Prode Mundial — Documento 4
## UX Sitemap + Screen-by-Screen Wireframe Brief

Documento de bajada UX exhaustiva del MVP.  
Puente entre la especificación funcional cerrada y el diseño implementable en frontend.

---

# 1. Propósito del documento

Este documento define con lujo detalle cómo debe estructurarse la experiencia de usuario del MVP de **Prode Mundial** a nivel de:

- arquitectura de navegación
- jerarquía de pantallas
- prioridades visuales
- componentes por pantalla
- estados vacíos / loading / error
- CTAs primarios y secundarios
- microcopys funcionales
- comportamiento mobile-first
- reglas de interacción
- criterios UX que luego Codex deberá respetar al construir frontend

No reemplaza la especificación funcional previa.  
La toma como verdad funcional y la traduce a una guía concreta de diseño y construcción.

---

# 2. Objetivo UX del MVP

La UX del MVP debe lograr simultáneamente 6 cosas:

1. **hacer entender el producto en segundos**
2. **llevar a la primera predicción lo más rápido posible**
3. **hacer visible qué tiene que hacer el usuario ahora**
4. **hacer visible cuánto sumó y cómo va en ranking**
5. **facilitar la creación o unión a ligas**
6. **mantener claridad extrema aun cuando existan reglas de scoring más ricas**

---

# 3. Principios UX obligatorios

## 3.1 Home utilitaria, no decorativa
La home no debe ser una pantalla institucional.  
Debe funcionar como tablero de acción.

## 3.2 Un CTA principal por bloque
Cada bloque principal debe tener una acción inequívoca.

## 3.3 Visibilidad permanente del estado
El usuario debe entender rápido si algo está:
- pendiente
- guardado
- editable
- bloqueado
- puntuado
- expirado

## 3.4 Predicción primero, explicación después
Nunca bloquear la acción principal con exceso de texto.

## 3.5 Mobile-first real
La experiencia crítica debe poder resolverse con el pulgar, en sesiones cortas y desde scroll vertical.

## 3.6 Ads fuera del momento crítico
Nunca insertar publicidad entre el input de predicción y el botón guardar.

## 3.7 Ranking y puntos siempre cerca
El usuario no debe “buscar demasiado” para saber cuántos puntos tiene o en qué posición va.

## 3.8 Deadlines visibles
Todo input editable debe mostrar deadline o cierre aplicable.

# 4. Convenciones base de layout

## 4.1 Breakpoints de diseño
### Mobile principal
- ancho de referencia: 360–430 px

### Tablet / desktop
- responsive adaptativo
- misma lógica funcional
- no rediseñar el producto como dashboard complejo

## 4.2 Estructura general mobile
Cada pantalla mobile debe contemplar:

1. **Top bar**
2. **Contenido principal en scroll vertical**
3. **Bottom navigation** en pantallas autenticadas principales
4. **Toasts / banners de feedback** para confirmaciones y errores

## 4.3 Safe areas
Diseñar contemplando notch, áreas seguras y bottom bars nativas.

## 4.4 Grilla conceptual
- padding horizontal consistente
- bloques en cards o secciones apiladas
- jerarquía clara por tamaño, peso tipográfico y separación vertical

## 8.1 Pantalla 01 — Landing pública

### Objetivo
Hacer entender el producto en menos de 10 segundos y llevar al usuario a:
- registrarse / jugar
- unirse a una liga

### Prioridad visual
1. propuesta de valor
2. CTA principal
3. CTA social
4. prueba de producto viva

### Estructura recomendada
#### Bloque 1 — Hero
- logo / nombre temporal
- headline potente
- subtítulo corto
- CTA primario: **Jugar ahora**
- CTA secundario: **Unirme a una liga**

#### Bloque 2 — Cómo funciona
3 pasos máximo:
- predice partidos
- suma puntos
- compite con amigos

#### Bloque 3 — Preview de partidos
- 2 a 4 cards ejemplo
- estados visibles
- CTA “Ver partidos” o “Empieza a predecir”

#### Bloque 4 — Preview ranking
- top 3 o top 5 teaser de una liga ejemplo
- CTA “Ver ligas”

#### Bloque 5 — Reglas resumidas
- exacto vs signo correcto
- competencia por ligas privadas
- ajuste post grupos

#### Footer mínimo
- reglas y puntos
- términos
- privacidad

### CTAs
- Primario: **Jugar ahora**
- Secundario: **Unirme a una liga**

### Estado si llega con invite token
La landing pública normal debe ceder prioridad al contexto de invitación y redirigir a la landing de liga.

### Microcopy sugerido
- “Predice el Mundial en segundos.”
- “Compite con amigos. Suma puntos cada día.”
- “Gratis. Simple. Mobile-first.”

## 8.5 Pantalla 05 — Home autenticada

### Objetivo
Ser el tablero central de acción diaria.

### Orden obligatorio de bloques
#### 1. Bloque de acción prioritaria
Debe mostrar lo más urgente:
- “Te faltan X partidos por predecir”
- o “La ventana de ajuste está abierta”
- o “Tus picks macro siguen abiertos”

#### 2. Partidos del día / próximos
- listado corto
- CTA a predecir / editar

#### 3. Resumen de puntos recientes
- puntos del último partido/día
- CTA a ver mis puntos

#### 4. Resumen de ranking
- posición en liga principal si existe
- acceso a mis ligas o a la liga destacada
- CTA ver rankings

#### 5. Bloque ligas
- si no tiene ligas: crear o unirse
- si tiene: ver mis ligas

#### 6. Bloque macro picks
- si siguen abiertos: progreso y CTA completar
- si están bloqueados: ver estado

#### 7. Ad inline no crítico
Solo entre secciones de baja sensibilidad.

### Estados posibles de home
#### Usuario nuevo sin predicciones
Home debe priorizar onboarding a primera predicción.

#### Usuario activo con pendientes
Home debe priorizar partidos próximos.

#### Usuario sin ligas
Home debe sugerir capa social.

#### Ventana de ajuste abierta
Card destacada arriba de todo.

### Microcopy sugerido
- “Hoy juegan estos partidos.”
- “Te faltan 3 predicciones.”
- “Subiste 12 posiciones.”
- “La ventana de ajuste está abierta.”

## 8.7 Pantalla 07 — Detalle / predicción de partido

### Objetivo
Permitir ingresar una predicción en el menor número de taps posible.

### Header
- volver
- fase
- fecha/hora local

### Bloque principal
- equipo local + flag
- input score local
- separador visual
- input score visitante
- equipo visitante + flag

### Bloque contextual
- deadline exacto
- estado del partido
- ayuda corta de scoring

### Comportamiento fase de grupos
- solo 2 inputs numéricos

### Comportamiento knockout
- 2 inputs numéricos de score 90'
- si hay empate predicho, desplegar selector obligatorio:
  - “¿Quién clasifica?”

### CTA primario
- **Guardar predicción**

### CTA secundario
- volver

### Mensajes inline
- “Puedes editar hasta el inicio del partido.”
- “Si predices empate, debes elegir quién clasifica.”

### Feedback post acción
- toast: “Predicción guardada.”

### Estado bloqueado
Inputs deshabilitados y copy:
- “Este partido ya está bloqueado.”

### Estado puntuado
Mostrar:
- predicción del usuario
- resultado oficial
- puntos obtenidos
- breve breakdown si aplica

## 8.8 Pantalla 08 — Predicciones macro

### Objetivo
Permitir completar picks de grupos + finalistas + campeón sin saturación cognitiva.

### Estructura general
- header con deadline global
- progreso de completitud
- secciones colapsables o apiladas

### Sección A — Grupos A-H
Por cada grupo:
- título de grupo
- selector de 1°
- selector de 2°
- validación de no repetición

### Sección B — Finalistas
- selector Finalista 1
- selector Finalista 2

### Sección C — Campeón
- selector campeón

### Reglas UX
- campeón debe pertenecer a finalistas
- finalistas no se pueden repetir
- grupos incompletos pueden quedar en draft
- bloque final inconsistente no puntúa

### CTAs
- **Guardar picks**
- opcional secundario: volver

### Estados visuales
- editable
- guardado parcial
- bloqueado
- ajustado (solo visualización posterior)

### Ayudas UX
- barra de progreso
- contador tipo “6 de 12 grupos completos”
- mensaje claro de cierre: “Cierran con el primer partido del torneo.”

### Microcopy sugerido
- “Guárdalos ahora y ajusta después solo donde esté permitido.”
- “Puedes completar esto por partes antes del cierre.”

# 11. Reglas de interacción críticas

## 11.1 Guardado explícito
No usar autoguardado en predicción de partido en MVP.

## 11.2 Sobrescritura simple
Editar una predicción debe sobrescribir la anterior sin exponer “borrar”.

## 11.3 Persistencia de contexto
Si login interrumpe una acción, al volver debe retomarse el flujo original.

## 11.4 Scroll y foco
Los formularios deben abrir teclado numérico apropiado y mantener visibilidad del CTA guardar.

## 11.5 Confirmaciones destructivas o irreversibles
Solo aplicar a:
- ajuste post grupos
- quizá abandono de flujo con cambios no guardados en macro picks

# 13. Reglas visuales funcionales para Codex

Especialmente en home:
- pendientes
- partidos del día
- ajuste abierto

## 13.2 Los scores deben ser gigantes comparados con texto secundario

Especialmente en ajuste post grupos.

# 17. Criterios de aceptación UX por pantalla

## 17.1 Landing
Se considera correcta si:
- explica valor rápido
- ofrece dos CTAs claros
- permite explorar sin login obligatorio

## 17.2 Login
Se considera correcta si:
- no rompe contexto
- permite entrar rápido con Google o magic link

## 17.3 Home
Se considera correcta si:
- prioriza lo urgente
- empuja a la siguiente acción útil

## 17.4 Partidos
Se considera correcta si:
- el usuario detecta rápido qué partidos tiene pendientes
- cada card comunica estado y CTA

## 17.5 Predicción de partido
Se considera correcta si:
- se completa en pocos taps
- el deadline está visible
- la validación de knockout es clara

## 17.6 Predicciones macro
Se considera correcta si:
- soporta draft parcial
- comunica progreso
- comunica cierre global

## 17.7 Ajuste post grupos
Se considera correcta si:
- deja claro que es único e irreversible
- deja clara la penalización

## 17.8 Rankings
Se considera correcta si:
- posición del usuario siempre visible
- ranking se entiende de un vistazo

## 17.9 Ligas
Se considera correcta si:
- crear y compartir una liga es trivial
- unirse por link o código no genera fricción excesiva

# 18. Riesgos UX que este documento busca evitar

## 18.1 Demasiada complejidad visible
Mitigación: bloques cortos, una acción principal por sección, reglas resumidas.

## 18.2 Usuario no sabe qué hacer al entrar
Mitigación: home accionable y priorizada.

## 18.3 Confusión entre score, estado y puntos
Mitigación: badges, cards y breakdown simples.

## 18.4 Fricción social excesiva
Mitigación: join league por link/código y copy claro.

## 18.5 Confusión con ajuste post grupos
Mitigación: pantalla dedicada, warning fuerte, comparación original vs nuevo.

# 20. Resumen ejecutivo final

Este documento baja el MVP de **Prode Mundial** a una estructura UX concreta, mobile-first y ejecutable.  
La idea no es producir diseño visual final, sino dejarle a Codex una guía suficientemente precisa para construir:

- rutas
- jerarquía de pantallas
- componentes
- estados
- CTAs
- reglas de interacción
- experiencia coherente con la lógica funcional ya cerrada

A partir de acá, el próximo paso correcto es convertir esta UX en una **especificación técnica de datos y backend** que elimine las últimas ambigüedades de implementación.
